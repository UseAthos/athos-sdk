title: Error codes
description: The REST error envelope and the full code-to-status table.
---

Every error from the REST API uses one envelope. Branch on `code`; `message` is human-readable and may
change.

```json
{
  "error": {
    "code": "CALL_NOT_FOUND",
    "message": "Call not found",
    "requestId": "req_2f8c1e94-3b6a-4d20-9a7e-1c5f0b8e2d44"
  }
}
```

The `requestId` matches the `X-Athos-Request-Id` response header — quote it in support tickets.

## Codes

| `code` | HTTP | Meaning |
| --- | --- | --- |
| `INVALID_REQUEST` | 400 | The request body or query was invalid (validation, bad cursor). |
| `DRILL_NOT_FOUND` | 400 | The `drillKey` doesn't match a known drill. |
| `INVALID_API_KEY` | 401 | Missing or invalid API key. |
| `API_KEY_REVOKED` | 401 | The API key was revoked. |
| `INVALID_TOKEN` | 401 | The session token was malformed or rejected. |
| `TOKEN_EXPIRED` | 401 | The session token expired before it was redeemed. |
| `TOKEN_ALREADY_USED` | 401 | The single-use session token was already redeemed. |
| `IP_NOT_ALLOWED` | 403 | The caller's IP is not on the allowlist (if one is configured). |
| `TENANT_INACTIVE` | 403 | Your tenant is inactive. |
| `TENANT_QUOTA_EXCEEDED` | 403 | Your tenant's monthly usage allowance is spent. It clears at the start of the next calendar month. |
| `CALL_NOT_FOUND` | 404 | No such call for your tenant (also returned for another tenant's call). |
| `SERVICE_UNAVAILABLE` | 503 | Athos is temporarily unavailable. Transient, but see the note below before retrying. |
| `INTERNAL_ERROR` | 500 | An unexpected error. Retry; if it persists, contact Athos with the `requestId`. |

## Which codes you'll see where

- **`POST /session`** (mint): `INVALID_REQUEST`, `INVALID_API_KEY`, `API_KEY_REVOKED`, `TENANT_INACTIVE`,
  `IP_NOT_ALLOWED`, `TENANT_QUOTA_EXCEEDED`.

  `TENANT_QUOTA_EXCEEDED` means your tenant's monthly usage allowance is spent. Retrying will not
  clear it: it lifts at the start of the next calendar month, or when your Athos representative
  raises the allowance.
- **`POST /roleplay/session`** (SDK redeem): `INVALID_REQUEST`, `DRILL_NOT_FOUND`, `INVALID_TOKEN`,
  `TOKEN_EXPIRED`, `TOKEN_ALREADY_USED`, `SERVICE_UNAVAILABLE` (no persona is available for the
  drill right now). These surface through the SDK's [`error` event](/sdk/errors). Most of them
  **spend the session token** — see [below](#a-failed-redemption-usually-spends-the-token).
- **`GET /calls` and `GET /calls/:id`** (reads): `INVALID_REQUEST` (list only), `INVALID_API_KEY`,
  `API_KEY_REVOKED`, `TENANT_INACTIVE`, `IP_NOT_ALLOWED`, and `CALL_NOT_FOUND` (detail only).

## A failed redemption usually spends the token

The session token is single-use, and it is **consumed as the request is redeemed** — before the
call is set up. So any failure raised after that point (`DRILL_NOT_FOUND`, `SERVICE_UNAVAILABLE`,
`INTERNAL_ERROR`) leaves the token spent: replaying the identical request returns
`TOKEN_ALREADY_USED`, even once the underlying condition has cleared. Recover by minting a **new**
session token and starting a new call.

The SDK's microphone codes (`MIC_PERMISSION_DENIED`, `NO_MIC_AVAILABLE`,
`MIC_DEVICE_DISCONNECTED`) never reach this endpoint at all: `connect()` gates on the microphone
before it redeems, so they leave the token unspent and the same token can be retried.

Of the codes this endpoint itself returns, only three are raised *before* redemption and leave the
token unspent: `INVALID_TOKEN`, `TOKEN_EXPIRED` and `INVALID_REQUEST`. Of those, only `INVALID_REQUEST` is worth retrying with the
same token — a rejected or expired token will not be accepted on a second attempt either. Treat
every other failure as having spent the token.
