---
title: Minting session tokens
description: Exchange your API key for a short-lived session token the SDK can use.
---

The browser SDK can't hold your API key, so your backend mints a short-lived, single-use **session
token** for it. Expose this as your own endpoint that your authenticated frontend calls.

A token is minted for a **registered agent**. Register each rep once with
[`POST /v1/agents`](/backend/managing-agencies-and-agents) before their first practice call — that is
the one-time setup cost per new person — and you mint with either of the agent's two ids, under the
same names the agent object uses.

## `POST /v1/session`

```http
POST https://app.useathos.ai/api/external/v1/session
Authorization: Bearer ath_live_…
Content-Type: application/json
```

**Request body**

Exactly **one** of:

<TypeTable
  type={{
    platformAgentId: {
      type: 'string',
      description:
        'The id you registered the rep under. An NPN or an email address is not an id — an unregistered value is 404 AGENT_NOT_FOUND.',
    },
    agentId: {
      type: 'string',
      description: 'The Athos agent id registration returned as agent.id.',
    },
  }}
/>

Sending neither, or both, is `400 INVALID_REQUEST`. `null` is treated as omitted.

<Callout type="info">
  The mint takes an **id** and nothing else. `GET /v1/agents` is the flexible "do you have this
  person?" lookup — it takes `npn`, `email`, `platformAgentId` or `agentId` as separate fields and
  returns the agent's `id`. Turn a handle into an id there, then mint with the id.
</Callout>

The agency id you used to send on every mint is now registered **once** on the agency
(`POST /v1/agents` or `PATCH /v1/agencies/{agencyId}` with `platformAgencyId`) and comes back as
`externalAgencyId` on every call and every delivery — the field did not go away, it moved.

**Response** `200 OK`

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9…",
  "expiresAt": "2026-06-05T18:05:00.000Z"
}
```

## Implement your token endpoint

Wrap `POST /v1/session` in your own authenticated endpoint so the API key stays on your backend and
you decide which rep the token represents.

<Tabs items={['curl', 'Node', 'Python']}>
<Tab value="curl">
```bash
curl -X POST https://app.useathos.ai/api/external/v1/session \
  -H "Authorization: Bearer $ATHOS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"platformAgentId":"rep_8842"}'
```
</Tab>
<Tab value="Node">
```ts
// Your endpoint, e.g. POST /athos/token
app.post('/athos/token', requireAuth, async (req, res) => {
  const r = await fetch('https://app.useathos.ai/api/external/v1/session', {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${process.env.ATHOS_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      platformAgentId: req.user.id,         // the id you registered the rep under; never client-supplied
    }),
  });
  const body = await r.json();
  res.status(r.status).json(body);          // { token, expiresAt } on success
});
```
</Tab>
<Tab value="Python">
```python
# Your endpoint, e.g. POST /athos/token
import os, requests

@app.post("/athos/token")
@require_auth
def athos_token():
    r = requests.post(
        "https://app.useathos.ai/api/external/v1/session",
        headers={"Authorization": f"Bearer {os.environ['ATHOS_API_KEY']}"},
        json={
            "platformAgentId": current_user.id,       # the id you registered the rep under; never client-supplied
        },
        timeout=10,
    )
    return r.json(), r.status_code   # { "token": ..., "expiresAt": ... }
```
</Tab>
</Tabs>

<Callout type="warn">
  Always derive the id you mint with from your **authenticated session**, not from the request body.
  A token scopes a live call to that rep; letting the client choose it lets one rep impersonate
  another.
</Callout>

## Rules of the road

- **Mint at the moment of use.** The token lives ~5 minutes and is single-use. Mint it when the rep
  clicks "start practice", hand it straight to `AthosRoleplay.create({ token })`, and connect.
- **One token per call.** Reusing a token returns `TOKEN_ALREADY_USED` at the SDK.
- **Server-to-server only.** This endpoint rejects cross-origin (CORS) requests — it must be called
  from your backend.

## Errors

| Status | `code` | Cause |
| --- | --- | --- |
| 400 | `INVALID_REQUEST` | Neither or both of `agentId` / `platformAgentId`, or a blank one. |
| 401 | `INVALID_API_KEY` | Bad or missing API key. |
| 401 | `API_KEY_REVOKED` | The key was revoked — rotate. |
| 403 | `TENANT_INACTIVE` | Your tenant is inactive. |
| 403 | `TENANT_QUOTA_EXCEEDED` | Your tenant's monthly usage allowance is spent. |
| 404 | `AGENT_NOT_FOUND` | No agent of yours is registered under that id. Register the rep first, or resolve a handle to an id with `GET /v1/agents`. |

Minting can fail with `403 TENANT_QUOTA_EXCEEDED` when your tenant's monthly allowance is spent. No
token is issued, and retrying will not help — the allowance lifts at the start of the next calendar
month. Surface it to the rep as "practice is unavailable this month" rather than as a retryable
error, and contact your Athos representative to raise it.

Full envelope and list: [error reference](/reference/errors).
