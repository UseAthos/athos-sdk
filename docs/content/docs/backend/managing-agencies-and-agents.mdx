---
title: Managing agencies and agents
description: Register your reps, get an agency for each customer for free, and look anyone up by the id you already hold.
---

Athos keeps a **roster** for your account: the **agencies** you serve and the **agents** (reps) in
each. Your backend maintains it with three calls: register, look up, update. Every call — practice
or real — is attributed to one agent and one agency on this roster, and the two ids registration
returns are what you use everywhere else.

## Register — `POST /v1/agents`

```http
POST https://app.useathos.ai/api/external/v1/agents
Authorization: Bearer ath_live_…
Content-Type: application/json
```

**Request body**

<TypeTable
  type={{
    firstName: { type: 'string', required: true },
    lastName: { type: 'string', required: true },
    email: { type: 'string', description: 'Stored lowercased.' },
    npn: { type: 'string', description: 'Non-digits are stripped; what is left must be 4–10 digits.' },
    platformAgentId: {
      type: 'string',
      description: 'Your own id for the rep. Unique within your account; may not begin with athos_agent_ or athos_agency_.',
    },
    agencyId: {
      type: 'string',
      description: 'Put the agent in this existing agency (an athos_agency_… id you were given). Omit it to create one.',
    },
    platformAgencyId: {
      type: 'string',
      description: 'Your own id for the agency. If one of your agencies already carries it the agent joins that agency; otherwise a new agency is created with it. Not together with agencyId.',
    },
  }}
/>

At least one of `npn`, `email` or `platformAgentId` is required. For every optional field, send it
or omit it — `null` is treated as omitted.

**Response** `201 Created`

```json
{
  "agent": {
    "id": "athos_agent_bR4kQ2wZ9Lp0nH3xVq1Yt",
    "firstName": "Dana",
    "lastName": "Reyes",
    "email": "dana@acme.test",
    "npn": null,
    "platformAgentId": "rep_8842",
    "agencyId": "athos_agency_V1StGXR8Z5jdHi6B-myT",
    "createdAt": "2026-09-16T14:02:11.000Z"
  },
  "agency": {
    "id": "athos_agency_V1StGXR8Z5jdHi6B-myT",
    "name": "Dana Reyes",
    "platformAgencyId": "acme-7731",
    "createdAt": "2026-09-16T14:02:11.000Z"
  }
}
```

With no `agencyId`, the agent is placed in a **new agency named after them** — there is no separate
"create an agency" step. Rename it whenever you like (below). To add a second rep to that agency,
send the same `platformAgencyId` again, or pass the agency's `id` as `agencyId`. An `agencyId` that
is not yours is `404 AGENCY_NOT_FOUND`.

**Already registered?** Registering a rep who already exists under any handle you sent is a
`409 AGENT_ALREADY_EXISTS`. `error.details` carries the existing ids and which handle matched
(`matchedOn` is one of `platformAgentId`, `npn`, `email` — the handles a registration can send), so
a create retried after a network timeout resolves in one call:

```json
{
  "error": {
    "code": "AGENT_ALREADY_EXISTS",
    "message": "An agent with that email is already registered",
    "requestId": "req_…",
    "details": {
      "agentId": "athos_agent_bR4kQ2wZ9Lp0nH3xVq1Yt",
      "agencyId": "athos_agency_V1StGXR8Z5jdHi6B-myT",
      "matchedOn": "email"
    }
  }
}
```

## Look up — `GET /v1/agents`

The "do you have this person?" call. Filter by **exactly one** handle and get that agent back — or
an empty `data` when nobody matches. A miss is a normal answer, **never a 404**; more than one
handle is `400 INVALID_REQUEST`.

| Param | Notes |
| --- | --- |
| `agentId` | The `athos_agent_…` id you were given. |
| `platformAgentId` | Your own id for the rep, as registered. |
| `npn` | Non-digits are stripped before matching; what is left must be 4–10 digits or the request is a `400`. |
| `email` | Matched case-insensitively. |
| `agencyId` | Restrict to one of your agencies (an id that is not yours is `404 AGENCY_NOT_FOUND`). Combines with a handle by AND. |
| `limit` | Page size, default `50`, max `100`. |
| `cursor` | Opaque token from a previous `nextCursor`. |

With `agencyId` alone it lists that agency's agents. With **no filter at all** it lists your whole
roster.

```bash
curl -G https://app.useathos.ai/api/external/v1/agents \
  -H "Authorization: Bearer $ATHOS_API_KEY" \
  --data-urlencode "email=dana@acme.test"
```

```json
{
  "data": [
    {
      "id": "athos_agent_bR4kQ2wZ9Lp0nH3xVq1Yt",
      "firstName": "Dana",
      "lastName": "Reyes",
      "email": "dana@acme.test",
      "npn": null,
      "platformAgentId": "rep_8842",
      "agencyId": "athos_agency_V1StGXR8Z5jdHi6B-myT",
      "createdAt": "2026-09-16T14:02:11.000Z"
    }
  ],
  "nextCursor": null
}
```

### Paging, once

Every list endpoint pages the same way: pass `limit` and the opaque `cursor` you were last given,
stop when `nextCursor` is `null`, and never parse a cursor. `GET /v1/agents` and
[`GET /v1/calls`](/backend/reading-calls) return the same `{ data, nextCursor }` envelope, so one
pager loop serves both.

## Update an agency — `PATCH /v1/agencies/{agencyId}`

Rename an agency and/or set your own id on it. Send only what you are changing; at least one field
is required, and `null` is treated as omitted.

<TypeTable
  type={{
    name: { type: 'string' },
    platformAgencyId: {
      type: 'string',
      description: 'Your own id for the agency. Unique within your account; may not begin with athos_agent_ or athos_agency_.',
    },
  }}
/>

```bash
curl -X PATCH https://app.useathos.ai/api/external/v1/agencies/athos_agency_V1StGXR8Z5jdHi6B-myT \
  -H "Authorization: Bearer $ATHOS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"Acme Senior Solutions"}'
```

**Response** `200 OK` — the updated agency object. An agency that is not yours answers
`404 AGENCY_NOT_FOUND`; a `platformAgencyId` already on another of your agencies answers
`400 INVALID_REQUEST`.

An agency created at a registration that sent no `platformAgencyId` has none; this is how it gets
one.

## What you cannot change (v1)

An agent's handles and agency are fixed at registration: there is no endpoint to update an agent, move
one to another agency, or remove one. A second `POST /v1/agents` for the same person is the `409`
above, never an update. If a rep's email, NPN or agency changes, ask your Athos contact. An agency's
`name` and `platformAgencyId` are the only roster fields you can change yourself (`PATCH` above).

## Your own ids

`platformAgentId` and `platformAgencyId` are **your** ids, stored and echoed back on every object,
call and delivery so you never have to map ours to yours (see
[Two id families](/concepts#two-id-families)). Two rules:

- Neither may begin with `athos_agent_` or `athos_agency_` — those are Athos ids. That is a
  `400 INVALID_REQUEST` everywhere.
- Each is **unique within your account**. A `platformAgentId` already registered answers
  `409 AGENT_ALREADY_EXISTS`. A `platformAgencyId` you already registered **joins** that agency at
  registration; only `PATCH /v1/agencies/{agencyId}` with another agency's value is
  `400 INVALID_REQUEST`.

The id you register a rep under is also what attributes their real calls — see
[Register your reps first](/backend/real-call-analysis#register-your-reps-first).
